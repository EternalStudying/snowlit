## Architecture and Configuration

Use native WXML/WXSS/JavaScript in `miniprogram/`, sharing the Spring Boot/MyBatis backend, MySQL, Redis, and object storage. The backend package is `xyz.snowlit` and its account table is `users`. Do not introduce cloud development or another business data source by default.

Add `services/<domain>.js` before page integration. Pages own interaction/state; uploads use the shared wrapper and `uploadQueue`, image selection uses `pickImages`, and page loads whose responses can race (filters, pagination, session changes) use `beginRequest`. Extract components when reused, without introducing a global store/event bus prematurely. Keep page files and registered routes consistent.

`CURRENT_ENV=dev` currently selects `http://localhost:8080` for APIs and uploads, as requested by the owner for local backend work. Relative media URLs resolve against the same origin. The prod profile retains `https://snowlit.xyz`; switching profiles is a source configuration change and requires recompilation. Select prod before uploading a package, since this is a static setting rather than an automatic runtime envVersion switch. Request/upload timeouts are 15/30 seconds. `fontFace=null` disables remote font requests. Localhost refers to the requesting device; physical devices need a reachable address that meets platform requirements.
Import `miniprogram/` with `miniprogramRoot=./`. AppID must match the backend and WeChat settings. Public `project.config.json` enables `urlCheck`, but local private settings can override it; physical-device/release validation must not depend on disabled checks.

Keep `lazyCodeLoading=requiredComponents` and `ignoreUploadUnusedFiles=true`; exclude tests and both specifications from packaging. Project targets are 2MB per main/subpackage, 500KB per page, and 200KB per image/audio asset; check current platform limits before release. New business media uses remote HTTPS. Keep the inline font, generic placeholders, and [font license](assets/fonts/OFL.txt).

## Identity, Sessions, and Failures

`wx.login` is exchanged and verified on the backend, which looks up the existing binding and issues a business token. `WECHAT_ACCOUNT_NOT_BOUND` leads to binding with a fresh code plus existing credentials. Preserve binding-conflict errors; do not register automatically or expose raw WeChat identity responses.
Use `Authorization: Bearer <business token>`. The client does not store `openid`, `session_key`, AppSecret, or provider keys. Backend checks enforce manager/authorship rules; client flags and roles control visibility only. Current manager IDs are 1 and 2, and `GET /api/auth/me` does not guarantee management flags.
Diary roles come from `users.couple_role`; missing roles fail explicitly. Creation can conflict for the same role/date; strict multi-couple `couple-id` isolation is not implemented.

| Local key | Meaning |
| --- | --- |
| `snowlit_token`, `snowlit_user` | Business session and display cache; clear on ordinary 401/logout; cached data grants no permissions |
| `snowlit_login_redirect` | Intended login return path, removed after reading |
| `snowlit_album_private_token_<id>` | Per-album access token/expiry; clear on expiry, invalidation, or logout |
| `snowlit_weather_auto_consent_v1` | Local automatic-location consent boolean, containing no GPS/weather and independent of login state |

Private albums use `X-Album-Access-Token`. Its invalidation clears only that album's token, not the business session. Check all HTTP statuses; 2xx succeeds, and upload responses require JSON parsing. Ordinary 401 clears the session and merges login prompts; login and private-album 401 retain separate semantics. Handle 403/404/5xx/network failures explicitly, without false success or unlimited retries.
Prefer Snowlit dialogs/toasts with native fallbacks. Pages need loading/empty/error/success states. Home/Wishes refresh in `onShow`; session changes clear private displays and reject stale responses.

## API and Data Contracts

These operations are consumed by `services/`; current source defines dynamic IDs, query details, and final backend permissions.

| Domain | HTTP operations | Key contract |
| --- | --- | --- |
| Login/binding | `POST /api/auth/wechat-login`; `POST /api/auth/wechat-bind-login` | `{code}` / `{code,username,password}` to `{token,user}` |
| Account/logout/profile | `GET /api/auth/me`; `POST /api/auth/logout`; `PATCH /api/auth/me/profile` | Update displayName/mood/bio; username/avatar remain read-only |
| Home/location | `GET /api/home`; `POST /api/home/location` | couple.startedOn, personStatuses, latest.diary.entryDate, latest.photo.previewUrl/takenAt |
| Weather | `GET /api/weather/atmosphere/browser` | latitude/longitude query; current 14-field response, independently degrading location/weather |
| Diary reads | `GET /api/diary/months`; `GET /api/diary`; `GET /api/diary/{id}` | Optional year, month as YYYY-MM; response entryDate |
| Diary writes/images | `POST /api/diary`; `PUT /api/diary/{id}`; `DELETE /api/diary/{id}`; `POST /api/diary/images` | Creation includes date; updates do not. contentMarkdown/moodKey/visibility; file upload returns uploadId/url |
| Moment reads | `GET /api/story/moments`; `GET /api/story/moments/{id}` | category/year filters; createdByUserId |
| Moment writes/images | `POST /api/story/moments`; `PUT /api/story/moments/{id}`; `DELETE /api/story/moments/{id}`; `POST /api/story/moments/images` | title/content/eventTime/endTime/locationName/address/longitude/latitude/category/images; file upload field |
| Album reads/access | `GET /api/albums`; `GET /api/albums/{id}`; `POST /api/albums/{id}/unlock`; `POST /api/albums/{id}/like`; `POST /api/albums/{id}/view` | Pagination/previewLimit; root detail canManage; optional originalUrl and previewUrl; UTC activity day |
| Album editing | `POST /api/albums/{id}/edit`; `POST /edit/photos`; `DELETE /edit/photos/{draftImageId}`; `DELETE /edit`; `PUT /api/albums/{id}`; `DELETE /api/albums/{id}` | services/album.js owns start/upload/remove/cancel/save/delete; mobile upload field file plus metadata; save uses ordered photoId/draftImageId entries; hasPassword without the password/hash |
| Album draft order | `PUT /api/drafts/album/images/order` | services/draft.js reorderDraftImages(kind, ids); listed ids first, unlisted images retained; album publish extra.imageOrder carries final order |
| Draft fields | `GET/PUT/DELETE /api/drafts/{kind}` | kind is album/diary/moment; GET returns draft or null, PUT replaces fields only; one draft per member/kind |
| Draft images | `POST /api/drafts/{kind}/images`; `DELETE /api/drafts/{kind}/images/{imageId}` | file; album adds caption/takenAt/location/width/height metadata JSON; opaque image id, no object names |
| Draft publication | `POST /api/drafts/{kind}/publish` | Latest fields plus album-only privatePassword/imageOrder; published response shape; no password stored |
| Wish reads | `GET /api/wishes`; `GET /api/wishes/{id}`; `GET /api/wishes/summary` | category/completed/page/size; lastOperatedByUserId |
| Wish writes | `POST /api/wishes`; `PUT /api/wishes/{id}`; `DELETE /api/wishes/{id}` | Creation uses multipart payload without an image; updates use JSON |
| Wish state | `POST /api/wishes/{id}/complete`; `POST /api/wishes/{id}/reopen` | Completion requires image; reopening has no image; backend requires authentication |
| Notices/feedback | `GET /api/update-notice?client=miniprogram`; `POST /api/update-notice/mute-today?client=miniprogram`; `POST /api/feedback/screenshots`; `POST /api/feedback` | Client isolation; screenshot file; submission imageUrls |

Wish categories are want_go/want_do. Completed queries use completed=true; pending queries use category plus completed=false. Write fields are title/category/description/locationName/expectedCompletedAt/note, preserving actual input.
Album UI-local `url` maps from previewUrl. Mobile uploads do not produce WebP original/preview pairs; the Web protocol remains separate. Diary titles are level-one Markdown headings; images upload before insertion. Incomplete/failed images block saving, and the backend validates references from Markdown rather than a separate image array.

Local-disk storage returns root-relative `/uploads/...` URLs. Album upload responses, list covers and detail cover/preview/original fields resolve them with `utils/media.js` before use by native image/preview APIs; otherwise the simulator treats them as bundle files. An optional mediaBaseUrl overrides the API origin. Empty fields and absolute CDN URLs remain unchanged. Stored records keep their server-side URLs.

## Location, Maps, and Dates

Initial automatic location follows this sequence: disclose foreground frequency/third-party processing, obtain consent, check privacy permission, check native location permission, call `wx.getLocation({type:'wgs84'})`, then request weather.

- Signed-in Home attempts an update on opening/login and every 20 foreground minutes. Hidden/unloaded pages stop timers and discard late results; return refreshes only when due. Cancellation/denial suppresses automatic prompts for the current run; manual retry can explicitly open `wx.openSetting`. No continuous background location.
- Use actual country/city results. Save a resolved location even without weather. Weather alone stays in current-session page memory without calling home/location or being overwritten by stale summaries. Complete failure retains previous values. Unknown fields use placeholders; missing temperature stays -- degrees and real zero stays zero.
- Raw WGS84 coordinates go to the Snowlit backend. Only the backend calls Geoapify/Open-Meteo, forwarding original validated coordinates and caching results by the exact coordinate pair. An optional Geoapify administrative point lookup repairs missing parent-city hierarchy; it sends the same original coordinates and preserves the basic result if it fails. Provider keys never enter the client. Missing Geoapify configuration can still allow weather alone. The location flow does not persist GPS/weather locally.
- The moments map uses existing GCJ02 business coordinates separately from Home's WGS84 flow. An empty map uses 0/0 at scale 3 solely as its viewport center. Records without coordinates stay in lists and skip markers. Clustering follows zoom; initial includePoints fits once, without resetting after dragging/layout changes. Editing uses manual coordinates, not chooseLocation.

`utils/date.js` parses plain `YYYY-MM-DD` as local calendar components, validating month lengths/leap years; invalid default months fall back to the current device month. Z/offset timestamps remain instants displayed in device local time. Do not conceal date bugs with a global fixed timezone. Album UTC activity days and ordinary calendar dates are separate contracts.

## Media, Privacy, and Platform Boundaries

| Flow | Limit | Protocol |
| --- | --- | --- |
| Diary | 20 images | file; backend 10MB per image, jpg/png/webp/gif |
| Moments | 3 images | file; submit business URLs after upload |
| Album creation/editing | 50 photos, nine per picker call | file + metadata: caption/takenAt/location/width/height; originals are picked to read EXIF, then `wx.compressImage` (quality 80) produces the uploaded file; a photo that cannot be compressed fails rather than uploading the original |
| Wish completion | 1 required image | image |
| Feedback | 3 images | file; submit imageUrls after all uploads succeed |

Check privacy before `wx.chooseMedia`, using image/compressed options (album creation/editing picks originals; see below). Cancellation is quiet; other failures are visible. Lock image lists and duplicate operations during selection/upload/submission, and recheck state when callbacks return. Diary batches run serially to prevent late insertion/index errors. Preserve compatibility with extensionless/generic-MIME WeChat files and backend content-header/size validation.
New albums, diaries and moments use `services/draft.js` and one `utils/draft-autosave.js` helper. It owns recovery/continue/discard, the 1500 ms debounce, one field save in flight, queued newest fields, hide/unload flush, retry status, and token-change shutdown. Diary exit begins flushing immediately and also awaits pending image deletion plus a final cleaned snapshot before stopping, without updating unloaded UI. `beginRequest` guards draft load/save/upload/remove/publish callbacks. Publishing drains uploads/field saves, pauses autosave without removing the token listener, then stops after success or resumes the same helper after failure; a delayed PUT must not recreate a published draft. Pages keep editing and navigation available according to their load/submission state; failed recovery stays locked for mutations but Back remains usable.

Only creation offers draft recovery/autosave; existing diary/moment edits retain their services and upload paths. Published-album edits use an internal, non-resumable album_edit row for newly picked photos only; it never enters the drafts API. In creation, the first change creates a draft, photos upload on pick via pickImages/uploadQueue, and a footer reports quiet save status. Native album picking is capped at nine per call across batches, while the shared album maximum is 50 (owner decision). Resume never slices away server images, including older drafts above the current cap; additions are blocked and images may be removed before publishing. Draft passwords are never included in fields, and private recovery requires re-entry. No destructive cleanup follows a failed publication.

Album edit mode never calls loadDraft or starts createDraftAutosave. It fills startAlbumEdit data, settles album date/place, uses the shared pick/EXIF/compress/upload pipeline, and builds save/password/last-photo rules in album-edit-presenter.js. Published photos are removed locally; unsaved photos also call removeAlbumEditPhoto. Save drains uploads and refreshes open album detail/list/Home pages; onShow reloads a marked detail. A member change clears the form and rejects old responses. wx.enableAlertBeforeUnload({message:'放弃修改？'}) begins on the first change and wx.disableAlertBeforeUnload runs after success. onUnload waits for uploads before best-effort cancelAlbumEdit. ALBUM_EDIT_EXPIRED stays visible; ALBUM_NOT_FOUND returns to Albums. Detail uses backend canManage, confirms deletion with the photo count, ignores duplicate taps and treats 404 as already deleted.

The grid accepts items {key,src,badge,message,progress}, columns (default 3) and disabled, and emits reorder {from,to} once on changed drop plus itemtap {index}. WXS binds native longpress (~350 ms) and touchmove; view-layer transforms lift the selected item while preserving its slot and sliding others. Early movement remains ordinary scrolling. JS measures rectangles at lift and only receives drop or edge-scroll commands, never each ordinary move. Within 80 rpx of an edge, small wx.pageScrollTo steps read back actual scroll offsets and stop at the page end. sortable-order.js exposes coordinate-slot and array movement rules. Only album creation/editing uses the component; creation persists uploaded IDs after each reorder and includes final imageOrder on publish.

The server owns draft images outside diary_uploads until publish. Discard/removal deletes their objects best effort after the row/list change commits. Diary publication promotes referenced images and deletes unused ones, preventing hourly temporary-upload cleanup from expiring drafts. Draft fields enforce table lengths, enums and date types; diary Markdown retains 60,000 characters plus the approved UTF-8/serialized-JSON byte ceiling. Missing photo takenAt uses album eventDate only at publication; missing locations stay unknown.
Paginate lists, keep a single setData under 256KB, and update only necessary paths frequently. Page exit clears timers/stale responses. Support iPhone SE through iPad.

`app.json` declares scope.userLocation and requiredPrivateInfos:getLocation. Disclosures for permissions, third-party location queries, accounts, media, feedback, devices, and caches must match WeChat backend privacy settings. `authorizePrivacy` prefers the page component and stops on explicit denial. Unsupported/failed platform checks currently may continue through the no-authorization-needed branch; this does not establish backend compliance.
Physical-device/release acceptance requires valid HTTPS/TLS and request/uploadFile/downloadFile domains, with reachable API/media paths. New platform capabilities require category, permission, and fallback checks; code is not proof of backend approval.

Album photo details ([photo-metadata.js](utils/photo-metadata.js)): album creation reads the first 256KB of each picked original and parses JPEG EXIF for the shooting date (`DateTimeOriginal`, else `DateTime`, kept as a camera-local calendar date) and GPS (unsigned RATIONAL/type 5 and signed SRATIONAL/type 10 components; 0/0 ignored). Each photo sends its own date as `takenAt`, falling back to the explicitly selected or EXIF-derived album date. New albums have no default date or location; validation requires a date, while missing locations remain empty on both client and backend. Untouched album fields take the earliest date and the place of the first photo with GPS; a field the person set, or one already filled from photos, is never refilled. The place comes from `GET /api/weather/atmosphere/browser` (silent; the backend sends original coordinates to Geoapify/Open-Meteo) formatted from the first two distinct known district, city, province and country components. District/city is preferred, a trailing city suffix is omitted for display, and unknown/duplicate components are skipped; a failed or empty lookup leaves the place empty. The page tracks pending metadata batches, disables the save button while reading/looking up places, and queues an early save until all pending work finishes. Removed-photo callbacks and unloaded-page callbacks cannot refill the form. Nothing found shows one toast and an inline hint; partial metadata shows the corresponding inline hint. Coordinates are not stored or sent anywhere else, and the album privacy prompt says time and place are read from photos; the WeChat backend privacy guide must say the same. This is best-effort: selected bytes may lack EXIF, and HEIC/PNG yield nothing with the current JPEG parser. On 2026-10-19, generated JPEG fixtures passed actual simulator filesystem reads, place lookup, compressed MinIO upload and metadata persistence; missing metadata stayed unknown. The supplied original was verified locally on 2026-10-20 and exposed the signed-GPS compatibility defect, now repaired. Native picker UI and physical devices remain unverified. Earlier cache results used the narrower parser and cannot establish that GPS metadata was absent from either cached or original files.

Privacy concerns actual identity/location data. Chinese UI, festivals, fonts, map providers, and package registries do not prove personal location. Preserve the project's existing public ICP filing information. Public moments can return recorded addresses/raw coordinates, and uploads other than album photos have no universal GPS/EXIF-removal step (diary/moments/feedback use WeChat compressed picks; that `wx.compressImage` and compressed picks drop EXIF on every device is not verified). Generic built-in images do not establish that future uploads lack location metadata. These are factual boundaries, not authorization to change visibility, upload protocols, or regional design.
